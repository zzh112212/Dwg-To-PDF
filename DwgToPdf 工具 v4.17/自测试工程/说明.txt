回归建议：--dir 全量 + 对比日志 [观测] 行。

v4.11：自测试工程源码直编（新增源文件须同步登记到 SelfTest.csproj 的

【工程简介】
SelfTest 是 DwgToPdf 的自测试程序，直接引用 源码工程 的 .cs 编译
（相对路径 ..\源码工程\，无第三方包），用于单元断言 + 真实端到端回归。
编译产物：SelfTest.exe（连同 extframe.lsp / extframe_company.lsp 输出到
bin\Release\net48\）。
v4.4：csproj 新增编译 ConvertReport.cs（批量转换报告）；
默认单元断言修正 3 条遗留陈旧断言（PISCES 比例期望值、plot 脚本窗口
ll/ur 坐标——原断言用 v3.8 方案 G 之前的旧公式，长期 FAIL，
现对齐现行实现，单元断言全 PASS）。

【构建命令】
  dotnet build "自测试工程\SelfTest.csproj" -c Release
运行（在 bin\Release\net48\ 下）：
  SelfTest.exe [命令] [参数]

命令速查
================================

【快速回归三件套（改代码后必跑，<1 分钟）】
  SelfTest.exe           默认：全部单元断言（PageSpec/FrameCache/Locator/
                         ExtractScript/PlotScript/PrintQuality/模板库/并发等）
  SelfTest.exe --sync    SmartConcurrency 并发调度单元测试
  SelfTest.exe --dc      动态任务池冒烟（24 个假 dwg 走完整流程，验证不丢不重）
  判定：三者全 PASS 即核心路径无回归。

【目录全量回归（真实端到端，需 AutoCAD，耗时较长）】
  SelfTest.exe --dir <输入目录> <输出目录>
                         目录全量回归（通用版识别链，真实出图）
  SelfTest.exe --dirc <输入目录> <输出目录>
                         目录全量回归（公司版识别链）
  SelfTest.exe --dirb <输入目录> <输出目录>
                         公司版 + 开启"识别块图框"（图框为块的图纸）
  SelfTest.exe --dirp <输入目录> <输出目录>
                         v4.17 修订三 新增：固定开始时刻（2026-10-15 09:08:07）连跑两轮，
                         验证 PDF 子文件夹同名自动追加 -2（输出 PDF-09：08：07 与
                         PDF-09：08：07-2，不应出现 -3；两轮间隔 <1 秒才复现同名）
  SelfTest.exe --dirs <输入目录> <输出目录>
                         v4.17 修订三 新增：两轮连跑 + 中途补一张新图纸，验证已成功的图纸
                         默认跳过（需求①）。判据看日志 done/todo 计数与旧 PDF 的
                         LastWriteTimeUtc 零改动——后者才是"没重打"的铁证，
                         日志文字可能骗人，文件时间戳不会。
  输出目录中按文件生成 PDF，可配合 _调查\measure_margins.py 做边距测量；
  v4.17 修订三 起批量边距改用 _测试输出\_m4.py（numpy 向量化，替代逐像素的 _m3.py，
  后者 4A0@150dpi 每张数千万次迭代会超时，见手册 32.5）：
    python _m4.py <pdf路径> [更多pdf路径...]   逐张打印 纸张尺寸 / 墨迹尺寸 /
                         L/R/T/B 边距(mm)；EMPTY 表示空页；dpi 写死 60
                         （判 3mm 阈值已足够，与 150dpi 结论一致）。
  汇总统计（空页数 / 边距<3mm 张数 / 全局最小边距 / 纸张分布）本轮用内联脚本
  对 _m4.py 输出二次加工，未单独存盘。

================================
v4.12 环境变量钩子（可复现验证）
================================
  DWGTOPDF_MAX_MB=<MB>        注入大文件阈值 → 超限文件退回「待处理」（不判失败）
  DWGTOPDF_TIMEOUT_SEC=<秒>   注入单张转换超时 → 超时中止该张并退回「待处理」
  DWGTOPDF_IGNORE_LIMITS=1    模拟"再次点击开始转换" → 本轮忽略大小/超时限制
用法（PowerShell）：
  $env:DWGTOPDF_TIMEOUT_SEC="3"
  & SelfTest.exe --dir <输入目录> <输出目录>
  Remove-Item Env:DWGTOPDF_TIMEOUT_SEC
预期（3 张约 20 秒的图纸、超时 3 秒）：
  日志出现 "[待转换] … 转换超时（>3 秒），已退回待处理"，结束行
  "成功 0 张，失败 0 张"；再加 DWGTOPDF_IGNORE_LIMITS=1 复跑 → 全部转出。

【经验要点】
- 改源码后跑快速回归三件套即可判断核心路径是否回归；简单 UI 改动
  不必重跑 --e2e-*（省 10+ 分钟）。
- 目录回归前先清空输出目录，避免旧 PDF 干扰对账。
- PDF 计数/快照断言必须递归（SearchOption.AllDirectories）：输出保留输入子目录
  结构，非递归 GetFiles 在输入含子目录时会把"有 PDF"数成 0（假失败）或漏掉新 PDF。
- v4.12：注入阈值类钩子时，--dir 的"PDF 数 == 输入数"断言会 FAIL（退回待处理
  既不算成功也不算失败）——属预期，不是回归。
- --dirb（块图框）：若块内没有闭合矩形（如 EQWE 只有 LINE+TEXT），该块会被
  块图框特征过滤掉；此时需在「设置 → 块名列表」加入块名（forced 路径）。
- 本工程引用源码用相对路径（..\源码工程\），移动目录后无需改引用。
- v3.9 提示：--dc 冒烟偶发 DirectoryNotFoundException 属已知环境抖动
  （经验手册 8.4：后台残留 AutoCAD 进程争用临时目录）；复跑稳定 PASS
  即非代码回归。复跑前先清残留进程（PowerShell Stop-Process）。
